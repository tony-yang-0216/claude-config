## /summary 輸出規範

### 硬性規則（違反任一條將導致 Notion 同步失敗）

**H1 — YAML Frontmatter 必須置於檔案最頂端**

輸出的第一行必須是 `---`，YAML 區塊之前不得有任何文字或空行：

```text
---
title: "精確的技術標題"
category: "CATEGORIES.json 中的 Key"
tags: ["標籤1", "標籤2"]
updated: "YYYY-MM-DD"
---
```

- `title`：從口語描述優化為精確技術用語（例如 "聊聊 JWT" → "JWT 身分驗證機制與安全性實踐"）
- `category`：從 `CATEGORIES.json` 的 Key 中選擇最精確的一個
- `tags`：2-3 個具備索引價值的關鍵標籤，避免口語詞彙
- `updated`：當天日期，格式 `YYYY-MM-DD`

**H2 — 清單最多 2 層巢狀，禁止第三層**

若邏輯複雜，用 H3 標題拆分，不用額外縮排。

**H3 — 單一文字段落禁止超過 1800 字元**

過長時必須強制使用雙換行拆分為獨立段落。

**H4 — 禁止 ASCII 框線繪圖**

禁止使用 `┌ ─ ┐ │ └ ┘ ├ ┤ ╔ ═ ╗ ║ ╚ ╝ ╰ ╮ ╭ ╯` 等字元（U+2500-U+257F 範圍）。

**H5 — 禁止全形引號**

YAML 值與正文一律使用半形雙引號 `"` 或半形單引號 `'`。

**H6 — 整份輸出必須是裸 Markdown，禁止用 code fence 包裹**

內文的程式碼片段仍正常使用 code block，但整份文件本身不可被包裹。

### 軟性規則（影響品質，但不影響同步）

**S1 — 使用 Mermaid.js 繪製流程與架構圖**

涉及流程、架構、層級關係時，必須使用 Mermaid.js（`graph` / `sequenceDiagram` / `flowchart`）。

Mermaid 語法規範：
- 所有節點標籤文字必須使用雙引號，例如 `ID["Label"]`
- 禁止在 ID 後直接緊接 `/` 或 `\`（應寫成 `A["/text"]`）
- 每個箭頭語句必須在同一行完成，禁止換行
- 標籤文字避免使用逗號或括號，建議以空格或破折號取代
- 輸出前心理模擬語法樹，確保括號與引號完全成對閉合

**S2 — 同類技術使用 Markdown table 對比**

對比時使用表格，表格必須包含完整的標題行與分隔線（`|---|---|`），確保列數一致。

**S3 — 程式碼區塊必須指定語言標籤**

語言名稱不可包含空格（使用 `csharp` 而非 `c#`，使用 `text` 而非 `plain text`）。

**S4 — 所有外部 URL 必須是完整絕對路徑**

以 `https://` 開頭。

### 標準筆記骨架

每份筆記必須依照以下章節順序組織內容。章節標題與子章節由對話內容動態決定，但必須對應以下骨架的語意目的。**若對話內容不足以支撐某章節，允許省略，並在筆記末尾「待補充」區塊列出省略的章節名稱。**

```text
# [筆記標題]

## 目錄
- [1. 是什麼](#1-是什麼)
- [2. 為什麼](#2-為什麼)
    - [2.1. 動機與背景](#21-動機與背景)
- [3. 怎麼運作](#3-怎麼運作)
- [4. 怎麼用](#4-怎麼用)
    - [4.1. 安裝與設定](#41-安裝與設定)
    - [4.2. 實作步驟](#42-實作步驟)
- [5. 使用場景](#5-使用場景)
- [6. 陷阱與最佳實踐](#6-陷阱與最佳實踐)
- [7. 延伸資源](#7-延伸資源)

## 1. 是什麼

定義核心概念，說明這個技術/工具/模式是什麼。
包含：精確定義、核心術語解釋、與相似概念的區別。

## 2. 為什麼

說明動機，解釋這個技術解決了什麼問題、為什麼需要它。
包含：歷史背景、痛點、它帶來的改善。

### 2.1. 動機與背景（依對話內容決定是否拆子章節）

## 3. 怎麼運作

深挖原理，說明底層機制與運作流程。
包含：架構圖或流程圖（Mermaid）、關鍵元件說明、資料流或控制流。

## 4. 怎麼用

實作導向，說明具體如何使用。
包含：安裝設定、關鍵參數與設定項、程式碼範例（完整且可執行）、異常處理。

## 5. 使用場景

說明適合與不適合的場景。
格式：使用表格對比「適合」與「不適合」，或條列具體情境。

## 6. 陷阱與最佳實踐

條列常見錯誤、邊界條件、安全性注意事項，以及推薦的做法。

## 7. 延伸資源

條列官方文件、延伸閱讀連結、後續可探索的主題。

---

## 待補充

- [列出因對話內容不足而省略的章節]
```

**正文標題必須帶有與目錄一致的層級編號**，格式如下：

```text
## 1. 主章節標題
### 1.1. 子章節標題
### 1.2. 子章節標題
## 2. 主章節標題
```

### 內容品質要求

- **完整性**：100% 保留對話中的技術細節，包含技術參數、邊界條件、邏輯分支、實作細節與異常處理。禁止對原始內容進行刪減或概括。
- **補充說明**：必要時加入說明性文字補充對話不足處，確保讀者能完全理解技術細節。
- **深度**：每個章節應包含 Why（動機）、How（機制）與具體範例，不只是定義。
